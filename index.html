❌ 6. 缩进的两种翻车：print 掉进循环 / 累加器被清零 第2章-1、2-11

症状：答案是 1 行，程序输出 79 行
原因：print 和循环体缩进相同 → 它在循环里面，每转一圈打印一次 
for i in range(12, m+1):
    s = s + i
    print(s)      # ❌ 缩进 4 格 = 在循环里

for i in range(12, m+1):
    s = s + i
print(s)          # ✅ 缩进 0 格 = 在循环外
用 4 个空格缩进（Python 官方规范）。层级看得清楚，不容易放错行。

——— 同一个根因，第二个症状：累加器被清零 ———

症状：累加求和的结果只等于最后一项（第2章-11 实测）
原因：初始化 s=0 和循环体缩进相同 → 它在循环里面， 每一轮开头都把前面累加的结果清零了 
s = 0                    # ✅ 和 for 同列 = 循环外，只在开头执行一次
for i in range(0, n-m+1):
    s = s + (m+i)**2 + 1/(m+i)

for i in range(0, n-m+1):
    s = 0                # ❌ 比 for 深一层 = 循环内，每一轮都清零
    s = s + (m+i)**2 + 1/(m+i)
s=0 的位置输入 1 3 的输出核对
循环外面（和 for 同列）sum = 15.833333✅ 2 + 4.5 + 9.333333
循环里面（比 for 深一层）sum = 9.333333❌ 只剩最后一项
# 放进循环里，内部过程是这样的：
第1轮: s=0 → s=2.0
第2轮: s=0 → s=4.5        ← 上一轮的 2.0 被抹掉了
第3轮: s=0 → s=9.333...   ← 4.5 又被抹掉了
为什么"放在上面任意位置都行"：
只要 s=0 在循环外面，它就只执行一次，作用仅仅是「给 s 一个初始值 0」。
放在 if 之前、if 之内、for 之前 —— 都在循环外，效果完全一样。
所以位置不重要，"在循环内还是循环外"才重要。
一个根因，两个完全不同的症状：
把语句多缩进一层，就把它从「循环外」搬到了「循环内」。
搬 print 进去 → 输出行数爆炸（第2章-1，答案 1 行却输出 79 行）
搬 s=0 进去 → 累加被清零（第2章-11，只剩最后一项）
Python 没有 {}，缩进就是语法。它不是在「排版好看」， 而是在告诉 Python 这条语句属于谁。

❌ 10. 字符串比较 ≠ 数字比较（排序和比大小都中招） 第2章-9、第3章-1

症状：判"部分正确"—— 单位数的测试点过了，多位数的挂了
原因：写了 map(str, ...)，于是 sorted() 按字典序排，不是按数值排
输入map(str) 排序map(int) 排序
4 2 82->4->82->4->8（一样）
10 2 810->2->8 ❌2->8->10 ✅
100 20 3100->20->3 ❌3->20->100 ✅
9 10 11->10->9 ❌1->9->10 ✅
print(*sorted(map(str, input().split())), sep="->")   # ❌ 按字典序
print(*sorted(map(int, input().split())), sep="->")   # ✅ 按数值
为什么单位数看不出来：只有一个字符时，字典序和数值序结果相同。
一旦出现多位数就分道扬镳 —— 字符串是逐字符比的：
"10" < "2" 为真（字符 1 比 2 小），但 10 < 2 为假。
所以排序前一定要先转成数字。
同一个原理，出了代码照样管 —— 文件名也是字典序：
我原来的自学文件叫 第2章-1_累加求和.py、…、第2章-10 输出华氏….py， 结果 第2章-10 排到了 第2章-1 前面。
原因跟上面一模一样：第2章-1 是 第2章-10 的前缀， 逐字符比到第 6 位才分出胜负 —— 一个是 0（48），一个是 _（95）， 0 小，所以带 10 的排前面。跟「1 和 10 谁大」毫无关系。
解法也只有补零一种：第02章-01_累加求和.py … 第02章-10_输出华氏-摄氏温度转换表.py， 让 01 和 10 在同一位上比。
顺带一个实测冷知识：换个排序算法也救不了 —— VS Code 用序数比较、PowerShell 用文化相关比较， 补零之前这两个算法给出不同的顺序（所以我在两处看到的顺序不一样）， 补零之后才完全一致。
同一个坑还有第二个出口：拿字符串比大小。
input().split() 出来的是字符串列表，直接拿去比就是逐字符比字典序。
实测 20 万组随机数的规律：
情况组数字符串比较 vs 数字比较，一致率
两个数位数相同163,655100.00%（永远一致）
两个数位数不同36,34550.04% —— 基本是抛硬币
150 vs 99     字符串 False   数字 True     ★ 不同
9   vs 150    字符串 True    数字 False    ★ 不同
150 vs 120    字符串 True    数字 True     一致（位数相同）
1000 vs 999   字符串 False   数字 True     ★ 不同
为什么位数相同就碰巧对：字符串逐字符比，而 '0' < '1' < … < '9'。 位数相同时从最高位开始比，效果和数字比较一模一样； 位数不同时先比的是「第一位」，跟真实大小无关。
这个 bug 最危险的地方：不报错、不崩溃，只是得到一个「一半概率正确」的答案。
所以：一读进来就转数字 —— nums = list(map(float, line.split()))。

多个值输出（sep 是"之间"的分隔符）

a, b, c = 1, 2, 3
print(a, b, c)              # 1 2 3        默认空格分隔
print(a, b, c, sep="->")    # 1->2->3
print(a, b, c, sep="")      # 123
print(a, b, c, sep=", ")    # 1, 2, 3

# end 控制结尾（默认是换行）
for i in [1, 2, 3]:
    print(i, end=" ")       # 1 2 3 （全在同一行）
print()                     # 手动换行
最容易踩的坑：sep 只在「一次打印多个值」时才有用。
只有一个值时，sep 被完全忽略： 
print(7, sep="-")         # 7       <- 不是 '7-' 也不是 '-7'
print(7, sep="!!!!!!!!")  # 7       <- 写什么都一样，直接无视
第3章-1 我写了 print(n, sep=" ", end="")，想每两个数之间加空格， 结果输出 '172180' —— 一个空格都没有。因为每次只传了 n 一个值， 根本不存在「之间」。
「每次打完补一个空格」是 end 的活，不是 sep 的活： 
print(n, sep=" ")    # ❌ sep 用不上
print(n, end=" ")    # ✅ 每个数后面跟一个空格（但结尾会多一个）
完整的三种写法（第3章-1 实测，输入 150 165 172 180 158，平均 165）： 
# ① 空格放 end —— 结尾多一个空格
for n in nums:
    if n > avg:
        print(n, end=" ")
# '172 180 '

# ② 先收集再一次性打印 —— 正好（推荐）
above = []
for n in nums:
    if n > avg:
        above.append(n)
print(*above)
# '172 180'

# ③ join
print(" ".join(str(n) for n in above))
# '172 180'
为什么 ② 能让 sep 生效？因为 * 把列表「摊开」成了多个参数：

⑨ 一行固定输出几个（第2章-14 用）

先说清楚 cnt 是什么

cnt 不是 Python 的关键字，也不是内置函数 —— 它只是随手起的变量名 （count「计数」的缩写）。换成 count、n、k 完全一样， 推荐用 count 更好读。
但 sum / max / min 绝不能当变量名 —— 它们是内置函数，被覆盖后会报 TypeError: 'int' object is not callable（见上面 ❌ 8）。

为什么非要自己数：for 给的是「值」，不是「第几个」

    print(x)          # 依次输出 -3 / 100 / 7

# x 是【数值本身】，它不知道自己是第几个。
# for 只负责给出值，不负责记数 —— 得自己拿个变量记。

cnt 三步曲

cnt = 0                  # ① 初始化，必须在循环【外面】
for x in range(A, B+1):
    cnt += 1             # ② 每轮加 1（等价于 cnt = cnt + 1）
    if cnt % 5 == 0:     # ③ 用余数判断「是不是第 5、10、15…个」
        ...

逐轮追踪（每行 5 个，-3~10）：

第几轮    x    打完后的cnt   cnt%5   动作

更省事的写法：enumerate() —— 内置的计数器，不用自己声明 
for cnt, x in enumerate(range(A, B+1), start=1):

enumerate 每轮同时给出序号和值；start=1 让序号从 1 开始（默认是 0）：
enumerate("abc") → (0,'a') (1,'b') (2,'c')　 enumerate("abc", start=1) → (1,'a') (2,'b') (3,'c')
一个容易搞混的差别：enumerate 的序号在每轮开头就更新好了， 所以直接写 if cnt % 5 == 0，不需要先 cnt += 1。

① 别拿「数值本身」当计数器。写成 if x % 5 == 0: print() 看着更短， 但那是在 x 等于 0、5、10 时换行，跟「打了几个」毫无关系 —— 只有数据刚好从 1 开始时两者才碰巧一致。
实测：1~12 时它看着是对的（5、5、2）；换成 0~10 一带负数就变成 4 个、5 个、5 个。

⑪ 遍历列表 + 挑出满足条件的元素

第一步：逐个取出（for 直接遍历元素，不用管下标）

heights = [150, 165, 172, 180, 158]

for h in heights:
    print(h)          # 150 / 165 / 172 / 180 / 158

# 只有需要知道「第几个」时才按下标取：

第二步：比大小（6 个比较运算符）

h >  avg    大于          h >= avg    大于或等于
h <  avg    小于          h <= avg    小于或等于
h == avg    等于          h != avg    不等于

# ⚠ 最常错：把「等于」写成 h = avg —— 那是赋值，不是比较

第三步：挑出来（三种写法）

avg = sum(heights) / len(heights)      # 165.0

# 写法一：收集到新列表（后面还要用就选这个）
above = []
for h in heights:
    if h > avg:
        above.append(h)
# -> [172, 180]

# 写法二：直接打印（不用收集）
for h in heights:
    if h > avg:
        print(f"{h:.2f}")

# 写法三：列表推导式（一行，和写法一完全等价）
above = [h for h in heights if h > avg]
模板（记住这个就够）： 
for x in 列表:
    if 条件(x):
        处理(x)        # 打印 / 收集 / 累加 / 数个数
「处理」有四种常见形态：
above.append(x) 收集　｜　print(x) 输出　｜　 cnt += 1 数个数　｜　total += x 求和
「大于平均值」这类题，顺序不能颠倒：
平均值要等所有数据都读完才能算出来，所以必须两趟 —— 先把数据存下来（list(map(...))），算完平均，再回头遍历一遍挑。
没法「读一个、判断一个」。

⑫ 列表推导式与生成器表达式（一行写出「筛选 + 变换」）

先看它替代了什么

# 普通写法：4 行
above = []
for h in heights:
    if h > avg:
        above.append(h)

# 列表推导式：1 行，结果完全一样
above = [h for h in heights if h > avg]

语法拆解

above = [  h    for h in heights    if h > avg  ]
           ↑    ↑                   ↑
      要放进去的  从哪个列表里取      满足什么条件才要
        东西                      （不筛选就整段省略）

四种常见形态（实测）

nums = [1, 2, 3, 4, 5]

[x for x in nums]                     # [1, 2, 3, 4, 5]      ① 原样搬（一般没意义）
[x for x in nums if x > 3]            # [4, 5]               ② 筛选
[x * 2 for x in nums]                 # [2, 4, 6, 8, 10]     ③ 变换
[x * 2 for x in nums if x % 2 == 1]   # [2, 6, 10]           ④ 筛选 + 变换 ← 最常用
第3章-1 实测（输入 150 165 172 180 158，平均 165.0）： 
[n for n in nums if n > avg]                # [172.0, 180.0]
[f"{n:.2f}" for n in nums if n > avg]       # ['172.00', '180.00']
print(*[f"{n:.2f}" for n in nums if n > avg])   # 172.00 180.00
「筛选 + 顺手转成两位小数的字符串」一行搞定 —— 这就是它比 for 循环省事的地方。

换成圆括号，就变成「生成器表达式」

[x * 2 for x in nums]     # 方括号 -> 立刻算完，得到一个列表（list）
(x * 2 for x in nums)     # 圆括号 -> 不立刻算，得到一个生成器（generator）
g = (x * 2 for x in nums)
print(g)                # <generator object ...>   看不到内容
print(list(g))          # [2, 4, 6, 8, 10]          转成列表才看得到
print(list(g))          # []                        ★ 生成器是一次性的！
生成器「一次性」和 map 对象是同一个道理（实测对照）：
map 对象：list(m) 第一次 [1,2,3]，第二次 []
生成器　　：list(g) 第一次 [1,2,3]，第二次 []
都是「惰性 + 一次性」，看过就空了。要反复用就先 list() 存下来。
什么时候用方括号、什么时候用圆括号：
· 结果要反复用（len()、切片、再遍历）→ 方括号，得到列表
· 只是喂给 join / sum / max 用一次 → 圆括号，省内存
一句话：要留下来就方括号，用完就扔就圆括号。

也能做字典和集合

nums = [1, 2, 3, 4]
{x: x * x for x in nums}    # {1: 1, 2: 4, 3: 9, 4: 16}   字典推导式
{x * x for x in nums}       # {16, 1, 4, 9}               集合推导式（自动去重）

注意：圆括号那对是生成器，不是「元组推导式」—— 元组没有推导式。

三个容易踩的点（都实测过）：
① 别用推导式做「打印」或「累加」。它只负责造一个新序列。
　 [print(x) for x in [1,2,3]] 确实会打印，但副作用是生成了一个全是 None 的列表 —— 　　副产品不是目的，直接写 for 循环。
　 sum([x for x in nums]) 能算，但 sum(nums) 就够了（不筛选不变换时多此一举）。
② 条件放「后面」是筛选，放「前面」是变换，两者完全不同：
　 [x for x in mixed if x > 0] → 元素变少了：[1, 3]
　 [x if x > 0 else 0 for x in mixed] → 元素一个都没少：[1, 0, 3, 0, 0] 　（后者是三目运算，不是筛选）
③ 变量不会「漏」到外面（Python 3 的推导式有自己的作用域）。 即使外面已经有同名变量也不会被改（实测：外面 x 是 999，跑完还是 999）。

⑬ 读多行（第一行是数量，后面 N 行数据）

核心就一句：input() 一次只读一行，读 N 行就调用 N 次。

三种写法（同一份输入，结果完全一样）

    s = input()           # 再读 n 行
    # 处理 s

# ② 全部读进来，按行切
import sys
lines = sys.stdin.read().splitlines()
n = int(lines[0])
for s in lines[1:1+n]:
    # 处理 s

# ③ 全部读进来，按空白切
import sys
data = sys.stdin.read().split()
n = int(data[0])
for s in data[1:1+n]:
    # 处理 s
关键区别：split() ≠ splitlines()（有空格时天差地别）
s = '110105194912310 02X\n12345678901234567 8' 
s.split()       # ['110105194912310', '02X', '12345678901234567', '8']   4 段！
s.splitlines()  # ['110105194912310 02X', '12345678901234567 8']         2 行 ✅
· split() 按任意空白切 —— 空格、换行、Tab 都算
· splitlines() 只按换行切 —— 空格保留
要「一行一行」处理就用 splitlines()；要「所有数字」不分行才用 split()。
四个会挂的地方（都实测过）：
① 只读一次 —— 只写了 s = input()，剩下 n-1 行根本没读。
② 行尾空格 / Windows 换行 → 用 .strip() 兜住：
　 输入 ' abc \n\n\nxyz\n' → 原始 [' abc ', '', '', 'xyz']， 　 strip 后 ['abc', '', '', 'xyz']
③ 空行会产生空字符串 '' —— 按行读又不过滤，数量就对不上。
④ 切片要写 lines[1:1+n]，不是 lines[1:] —— 万一输入末尾有多余空行，lines[1:] 会把空字符串也算进来。
用了 sys.stdin.read() 之后不能再 input() —— 流已经读到末尾了：
EOFError: EOF when reading a line
两种读法只能用一种，不能混着来。
性能差别可以忽略：100 行输入，逐行 input() 0.043 秒，一次 read() 0.039 秒。
选看得懂的那种。新手写这题建议逐行读 —— 最直白。

三、符号速查：* 和 []

——— 第一部分：星号 * ———

一句话核心：* = 摊开 / 收拢，方向取决于它站在哪一边。
在调用 / 取值的地方 → 摊开（一个整体拆成多个）
在定义 / 赋值的地方 → 收拢（多个装成一个）

① 调用时摊开（最常用）

nums = [2, 4, 8]

print(nums)              # [2, 4, 8]    传进去的是【1 个】列表
print(*nums)             # 2 4 8        摊成【3 个】参数
print(nums, sep="->")    # [2, 4, 8]    sep 没生效！
print(*nums, sep="->")   # 2->4->8      ✅
为什么 print(nums, sep="->") 不行：sep 是"多个参数之间"的分隔符。只有 1 个参数时没有"之间"，用不上。
星号做的事：把 [2, 4, 8] 这个整体，摊成 2、4、8 三个独立参数。

② 定义函数时收拢：*args

def show(*args):
    print(args)

show(1)          # (1,)
show(1, 2, 3)    # (1, 2, 3)
show(*nums)      # (2, 4, 8)   传进去时摊开，函数里又收拢成元组

③ 赋值时收拢：a, *rest = ...

a, *rest = [1, 2, 3, 4]
# a = 1,  rest = [2, 3, 4]

first, *mid, last = [1, 2, 3, 4, 5]
# first = 1,  mid = [2, 3, 4],  last = 5

④ 双星 ** 是"字典版"

def info(**kwargs):         # 收拢关键字参数成字典
    print(kwargs)
info(name="黄", age=18)      # {'name': '黄', 'age': 18}

{**d1, **d2}                # 合并字典

⑤ 别搞混：两个值"之间"的 * 是乘法

写法结果含义
2 * 36数字相乘
'3' * 5'33333'字符串重复（第2章-7 用过）
[0] * 3[0, 0, 0]列表重复
2 ** 38幂运算（双星）
(-1) ** (i+1)±1 交替符号交替（第2章-6 用过）

一表总结

写在哪例子含义
两个值中间a * b乘法 / 序列重复
函数调用里f(*seq)摊开成多个参数
函数定义里def f(*args)收拢成元组
赋值左边a, *rest = seq收拢成列表
两个值中间a ** b幂
函数定义里def f(**kw)收拢成字典
函数调用里f(**d)摊开字典成关键字参数
口诀：调用摊开，定义收拢；左边收拢，右边摊开。单星管序列，双星管字典。

——— 第二部分：中括号 [] ———

三个身份：
[1, 2, 3] → 造一个列表
nums[0] → 索引：取出一个元素
nums[1:3] → 切片：取出一段
记忆：括号里是"内容" → 造列表；是"数字或冒号" → 取东西。

① 创建列表

[1, 2, 3]                 # [1, 2, 3]
[]                        # []              空列表
[0] * 3                   # [0, 0, 0]       序列乘法
list(range(5))            # [0, 1, 2, 3, 4]
[x*2 for x in [1,2,3]]    # [2, 4, 6]       列表推导式

② 索引：取【一个】元素

nums = [10, 20, 30, 40, 50]
nums[0]    # 10    第一个（从 0 开始数！）
nums[2]    # 30
nums[-1]   # 50    最后一个（负数从右边数）
nums[-2]   # 40    倒数第二个

"Python"[0]   # 'P'     字符串也能索引
"Python"[-1]  # 'n'

nums[10]      # IndexError: list index out of range   越界报错

③ 切片：取【一段】 —— [起:止:步长]，左闭右开

nums = [10, 20, 30, 40, 50]

nums[1:3]    # [20, 30]             第1到第2个（不含3）
nums[:2]     # [10, 20]             前两个（冒号前省略 = 从头）
nums[2:]     # [30, 40, 50]         从第2个到末尾
nums[:]      # [10,20,30,40,50]     全部（相当于复制一份）
nums[::2]    # [10, 30, 50]         隔一个取一个（步长 2）
nums[::-1]   # [50,40,30,20,10]     反转！

"人生苦短，我学Python"[::-1]   # 'nohtyP学我，短苦生人'
[::-1] 我已经用过两次：
第1章「逆序三位数」：a[::-1] 把 "530" 变成 "035"
第2章-9 降序：sorted(nums)[::-1]

④ 修改元素

a = [1, 2, 3]
a[0] = 99         # a = [99, 2, 3]
a[1:3] = [7, 8]   # a = [99, 7, 8]      切片也能赋值

# ⚠️ 字符串不能改（不可变类型）
s = "abc"
s[0] = "X"        # TypeError: 'str' object does not support item assignment

⑤ 字典也用中括号

d = {"name": "hkh", "age": 18}
d["name"]           # 'hkh'      索引 = 按键取值
d["age"]            # 18
d["city"] = "武汉"   # 新增 / 修改
d.get("x", 0)       # 0            键不存在时返回默认值（不报错）

d["x"]              # KeyError: 'x'   直接索引不存在的键会报错

⑥ 三种括号的分工

括号用途例子
()元组 / 函数调用 / 分组(1, 2)、print(1)、(1+2)*3
[]列表 / 索引 / 切片 / 推导式[1,2]、nums[0]、nums[::-1]
{}字典 / 集合 / f-string 表达式{'a':1}、{1,2}、f"{x}"

⑦ 三个最容易错的点

1. 从 0 开始数，不是从 1
[10, 20, 30] 的下标是 [0] [1] [2] —— 第一个是 [0]。

2. 切片不含结尾
nums[1:3] 得到 [20, 30]，不是 [20, 30, 40]。

3. 索引和切片写法不同
第 2 个元素 → nums[1]；前 2 个元素 → nums[:2]

四、报错速查表

报错含义怎么办
SyntaxError 语法错，程序一行都不跑 先看有没有全角标点；看报错里的行号
invalid character '：' (U+FF1A) 全角标点 把 ： 改成 :
invalid literal for int() with base 10: 'a,n' 想转成整数，但它不是整数 看单引号里的内容 —— 那就是程序实际读到的
invalid literal for int() with base 10: '10.5' 输入是小数，却用了 int() 改成 float()
int() can't convert non-string with explicit base 带进制时第一个参数是整数 第一个参数保持字符串
'str' object cannot be interpreted as an integer 该给整数的地方给了字符串 比如 int() 的第二个参数要 int(b)
'int' object is not callable 函数名被当成变量用了（如 sum = 11） 换个变量名
关键区分：
SyntaxError = 语法错，程序根本没开始跑 → 改运行时逻辑没用！
ValueError / TypeError = 运行时错，跑到那一行才崩。

3-1 大于身高的平均值 通过 10/10

要求：一行输入全班身高（空格分隔的正整数），输出其中超过平均值的那些身高， 顺序与输入相同，每个数后面跟一个空格。
样例：143 174 119 127 117 164 110 128 → 143 174 164 （末尾那个空格是要求里的）

我的代码

nums=list(map(int,input().split()))
avg=sum(nums)/len(nums)
for n in nums:
    if n>avg:
        print(n,end=" ")
这题最关键的一点：输出末尾【就是要有一个空格】。
题目原文写着「每个数后面有一个空格」，所以 end=" " 是正确写法，不是「将就」—— 换成 print(*above) 反而会少掉末尾那个空格，可能判格式错误。
先读题目对输出格式的原话，再决定用哪种写法。
我第一版挂在 sep 上：
写的是 print(n, sep=" ", end="")，想靠 sep 加空格， 结果输出 '172180' —— 一个空格都没有。
原因：sep 管的是「一次 print 里多个值之间」，而这里每次只传了一个 n， 不存在「之间」，所以 sep 被完全忽略（print(7, sep="!!!") 也只会输出 7）。
「每次打完补一个空格」是 end 的活。
把 end 的归属说准确：
end 属于每一次 print() 调用，不属于循环 —— 循环只是让 print() 被调用了很多次。
证据：print("a", end=" "); print("b", end=" ") 里没有循环，照样输出 'a b '。
这题为什么必须两趟：平均值要等所有身高都读完才算得出来， 所以必须先把数据存下来（list(map(...))），算完平均再遍历一遍挑 —— 没法「读一个、判断一个」。这是第 3 章的第一个思维转弯。
